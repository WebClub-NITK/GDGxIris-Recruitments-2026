## Project Overview: What is LeetSync?

**LeetSync** is a browser extension that silently bridges the gap between a developer's LeetCode grinding and their GitHub profile. It automatically captures successfully passed code submissions on LeetCode and commits them directly to a linked GitHub repository.

Instead of manually copying and pasting solutions after solving a problem, LeetSync acts as an invisible background agent. It verifies that the test cases passed, extracts the source code, formats it, and uses the GitHub API to push the code, keeping the user's open-source contribution graph active and their competitive programming journey well-documented.

## What Should the Final Output Look and Act Like?
Imagine a two-part experience: a configuration popup and an invisible background process on the LeetCode website:

1. **The Extension Popup (Control Panel):**
   - A `[ Authenticate with GitHub ]` button to initiate the OAuth flow.
   - A dropdown or input field to select/create the target repository (e.g., `my-leetcode-solutions`).
   - A status indicator showing the currently linked account and repo.

2. **The LeetCode Interface (Content Script):**
   - The user writes code and clicks "Submit" as usual.
   - The extension monitors the page state. When the glowing green "Accepted" screen appears, it extracts the code.
   - A small, non-intrusive toast notification pops up on the LeetCode screen: `Successfully pushed to GitHub!`.

## Core Features to Implement (Mandatory)

### 1. GitHub OAuth 2.0 Authentication Pipeline
- Implement a secure OAuth flow using the `chrome.identity` API (or equivalent for Firefox/Edge) to request authorization from the user's GitHub account.
- Securely store the returned access token in the browser's local storage (`chrome.storage.local`).
- Ensure the token includes the necessary scopes (like `repo`) to read and write files to the user's repositories.

### 2. LeetCode DOM Observation & Interception
- Inject a Content Script into `leetcode.com/problems/*`.
- Use a `MutationObserver` or intercept network requests to detect when a submission completes successfully (specifically looking for the "Accepted" state).
- Extract the problem title, problem ID, programming language used, and the raw code string directly from the DOM elements or the internal Monaco Editor instance.

### 3. GitHub REST API Integration
- Format the extracted code and create a specific file path (e.g., `ProblemName/solution.ext` based on the language).
- Ping the GitHub API (`PUT /repos/{owner}/{repo}/contents/{path}`) to create or update the file.
- Handle commit messages automatically (e.g., `"Auto-commit: Solved 001. Two Sum in C++"`).

## Technical Specifications & Implementation Guidelines

When building this application, ensure the system is designed to handle real-world edge cases by implementing the following technical requirements:

*   **Duplicate & Version Control:** The extension must check if a solution for a specific problem already exists in the repository. If the user submits a *better* solution (e.g., faster runtime), it should overwrite the existing file and include an updated commit message. It should not push the exact same code twice.
*   **Token Security & Expiry Management:** OAuth tokens expire or can be revoked. Before attempting to push code, the extension must validate the token. If the GitHub API returns a `401 Unauthorized`, the extension should gracefully catch the error, halt the push, and prompt the user via the extension badge to re-authenticate.
*   **Asynchronous Content Scripting:** LeetCode is a heavy Single Page Application (SPA) built with React. Elements render dynamically. Your DOM extraction logic must rely on asynchronous waiting patterns or robust selectors, as the code block and success message will not be present immediately when the page loads.
